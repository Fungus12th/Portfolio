GraphOS

A next-generation Project-Oriented Operating System built around a graph-native execution model (Draft v0.1).

Abstract

GraphOS is a next-generation Project-Oriented Operating System (ProjectOS) built around a graph-native execution model. Unlike traditional operating systems where the filesystem is the primary abstraction, GraphOS introduces the Project as the first-class computational unit.

Every component within the system—projects, code modules, AI agents, datasets, containers, services, documents, workflows, and devices—is represented as interconnected Entities inside a persistent graph.

The filesystem continues to exist internally for compatibility, but users interact primarily with projects and their relationships rather than directories and files.

Core Principles

  • Project First
  • Graph Native
  • Entity Based
  • AI Ready
  • Event Driven
  • Modular
  • Plugin Oriented
  • Local First
  • Cross Platform Compatible
  • Developer Centric

High-Level Architecture

At its core, GraphOS sits above the Linux kernel (in Version 1) but replaces traditional user-space interactions with a Unified Command Bus and Graph Runtime. Everything above the kernel communicates through the Graph Runtime. Entities flow from the Entity Engine through the Graph Store and Filesystem Adapter (via FUSE) to maintain compatibility with existing tools while fundamentally shifting the execution paradigm.

The Graph Runtime & Entity Engine

This is the heart of GraphOS. The runtime manages Entity Graphs, Relationship Graphs, Dependency Graphs, Resource Graphs, Execution Graphs, and Permission Graphs. Nothing exists outside the graph.

Every object (Project, Code Module, Document, Database, AI Agent, Workflow) becomes an Entity with an ID, Type, Metadata, Relationships, Capabilities, Permissions, Version, and State.

Example relationships: Backend -> depends_on -> Database or Dataset -> used_by -> AI Model.

Filesystem Adapter (FUSE)

Users never interact directly with traditional storage. The filesystem is dynamically generated for compatibility with VS Code, Git, compilers, and existing apps.

When a user edits a virtual file, the Entity Graph updates automatically. Storage is an implementation detail (using SQLite, RocksDB, etc.), eventually moving to a Native Graph Store.

Version Roadmap

  • v0.1: Linux-based, Graph Runtime, Entity Engine, Project Runtime, CLI, Basic GUI.
  • v0.5: Workflow Scheduler, Capability Engine, Plugin SDK, Visual Graph.
  • v1.0: Bootable ISO, Project Workspace, AI Runtime, Graph Explorer.
  • v2.0: Native Graph Filesystem, Distributed Projects, AI-assisted Scheduling.
  • v3.0: Research Kernel, Native Graph Memory Manager, Graph-based IPC.
