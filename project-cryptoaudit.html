Crypto-Audit

A cryptographic data provenance and integrity verification system that uses Merkle trees and Ethereum smart contracts to create immutable, tamper-proof audit trails for AI training datasets.

The Problem

AI companies train models on massive datasets. But how do you prove a dataset hasn't been tampered with? How do you guard against undetected dataset poisoning, post-hoc alterations, or intellectual property disputes?

Storing dataset hashes in a traditional database relies on trusted administrators who could alter records. Crypto-Audit eliminates that trust requirement by anchoring proofs on the Ethereum blockchain — immutable, timestamped, and publicly verifiable by anyone.

How It Works

  • Step 1 — Hash & Build: Recursively walks a target directory, hashes every file with SHA-256 (in 8KB streaming chunks), sorts paths alphabetically for deterministic output, and constructs a binary Merkle tree bottom-up.
  • Step 2 — On-Chain Attestation: The single 32-byte Merkle root, along with dataset version, creator ID, and notes, is submitted to the AuditRegistry.sol smart contract on Ethereum.
  • Step 3 — Tamper Detection: If any single byte in any file changes, the SHA-256 hash changes, propagating up every ancestor node to the root. Tampering is mathematically impossible to hide.
  • Step 4 — Inclusion Proofs: Generate a compact O(log N) Merkle proof for any individual file to prove it belongs to the certified dataset — without revealing or transferring the entire dataset.

Smart Contract Features

  • Immutable Record Storage: Each audit record stores the Merkle root, dataset version, creator, notes, submitter address, and block timestamp.
  • Duplicate Root Rejection: Prevents the same Merkle root from being registered twice, reverting with a custom DuplicateRoot error.
  • Role-Based Access Control: Owner-managed whitelist of authorized auditors. Only whitelisted addresses can submit records.
  • Emergency Circuit Breaker: pause() and unpause() functions for emergency situations.
  • Gas Optimized: Uses Solidity custom errors instead of expensive require(..., "string") patterns.

Command-Line Interface

  • audit.py hash-dataset <folder> — Scan a folder, print per-file hashes, build Merkle tree, and output the root.
  • audit.py prove <file> --dataset <folder> — Generate a Merkle inclusion proof for a specific file (terminal + JSON export).
  • audit.py verify <file> --dataset <folder> --root <hash> — Verify a file against an expected Merkle root.
  • submit_root.py — Submit the Merkle root to the blockchain with pre-submission duplicate checks.
  • read_blockchain.py — Dump all on-chain audit records with formatted UTC timestamps.

Testing

16 automated Mocha/Chai tests covering record storage, event emission, ownership, unauthorized rejection, auditor management, pause/unpause flow, duplicate root rejection, empty root validation, backward compatibility, and record counting.
